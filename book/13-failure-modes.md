# 13 · Failure Modes & Edge Cases

> **What you'll be able to answer after this chapter:** every known way the mod or the pipeline fails, the symptom you see, the cause, and how it is fixed; for in-game failures also how it is detected. Terms used below: the *diff* is the mod's `libraries/sound_library.xml` patch, the *redirect* is the part of it that points Boso Ta's six sound entries (`10201_normal`, `10201_normal_npc`, `10201_comm`, `10201_comm_signalleak`, `10201_comm_npc`, `10201_comm_broadcast`) at `extensions\<id>\voice\10201\normal`, and `<id>` is the variant's `id` from `config/variants.json`, which is also the extension's folder name ([ch. 2](02-core-concepts.md), [ch. 4](04-variants-configuration.md), [ch. 5](05-building-and-validating.md)).

## In the game

The log referred to below is `debuglog.txt` in `Documents\Egosoft\X4\<user id>\`, written when X4 is started with `-logfile debuglog.txt`. That option also makes X4's own script errors flash on screen; `-debug all` is only needed for file I/O messages (`docs/dev-team/LESSONS.md:46`). The diff error text "No matching node" was verified in phase 0 (`docs/phase0-findings.md:45`).

| Symptom | Cause | Detect | Fix |
|---|---|---|---|
| Boso sounds unchanged | the diff was not applied: a wrong sound id in `config/variants.json`, the extension disabled, or `content.xml` malformed | `validate_mod.py`; in the log, search for "No matching node" and the mod id | wrong id: correct it in `config/variants.json`, rebuild, validate; disabled: enable it in the game's Extensions menu; malformed `content.xml`: see next row |
| Mod missing from the Extensions list | `content.xml` not well-formed (classic: a raw `&`) | `validate_mod.py` | rebuild with `build_mod.py`, which escapes every value; never edit `dist/` by hand |
| Boso completely silent, audio missing | the audio was not installed | count the files in `extensions/<id>/voice/10201/normal/`: 2,324 for a German, 1,750 for an English variant on 9.00 | run `install_mod.py <variant>` again with X4 closed |
| Boso completely silent, wrong folder | the extension folder name differs from the `id` the redirect was built with | compare the folder name in `extensions/` with `id` in its `content.xml` | rebuild and install so both match |
| Boso completely silent, Workshop item | a build with a `bosota_*` id was uploaded to the Workshop, which installs it as `ws_<number>` | the subscribed folder `ws_<number>` holds a `content.xml` with a different id | upload the Workshop variant (`alien_ws`, `alien_en_ws`), whose `id` is `ws_<number>` ([ch. 8](08-installing-and-releasing.md)) |
| Boso completely silent after swapping | the mod was replaced while X4 was running | — | close X4, reinstall, start again |
| Single lines silent | the game has line ids the mod folder lacks (after a patch or DLC) | `check_coverage.py` | lines with text: generate them with the variant's `audio_recipe` (`process_audio.py`, or `tts-batch` for Will) for the ids `check_coverage.py` reports; the five textless ids (see "Edge cases in the data") cannot be generated by TTS, copy them from the processed originals (`build/audio/d12_alien_mid_g9`) |
| English player hears German | the German variant is installed on an English voice track | — | install the variant matching the voice language |
| Boso quiet or muffled when you turn away | positional audio (`is3d`) and occlusion (muffling by obstacles) on a dark voice | — | `is3d="0"` and `noocclusion="true"` are already set in all variants; if it still happens, check them in the validator report and see the next row |
| Boso "too quiet" although measured loudness matches the original | equal LUFS (integrated loudness) is not equal perceived loudness in the game mix: a heavily lowered voice measured −22 LUFS like the original but carried 11 dB less above 1 kHz (`docs/dev-team/LESSONS.md:23`, `docs/HISTORY.md:39`) | listen in the game | render again with a higher `--gain-db` of `process_audio.py` (the variants use +4 to +9) or a chain with stronger mid-range emphasis ([ch. 6](06-audio-processing.md)) |
| Lips out of sync (German) | TTS lines have their own length | — | accepted trade-off |
| Comm messages lack the radio filter | all six sound entries, including the four `10201_comm*` ones, read the one processed `normal` folder | — | accepted; separate comm audio would need a second audio folder and redirect |
| Brief red text on screen | X4's own script errors, shown on screen when `-logfile` is active | the log | remove `-logfile` after testing |
| Save marked "modified" | any unsigned extension; `save="0"` does not avoid it ([ch. 8](08-installing-and-releasing.md)) | — | unavoidable for mods |
| Two variants active | a subscribed Workshop item (`ws_<number>`, installed in the game's `extensions` folder) next to a local `bosota_*` build, or two manual copies | list `extensions/` | unsubscribe or remove the local build; the installer only removes `bosota_*`, never `ws_*` |

In the Detect column, "—" means there is no log entry or tool check; the symptom itself is the signal.

## In the pipeline

| Symptom | Cause | Fix |
|---|---|---|
| `install_mod.py` reported success but no audio arrived (installer versions before 2026-10-24) | the audio copy depended on a configuration field that a clean-up had removed | fixed: the installer now always copies the audio and checks for it before copying; update the repository and install again |
| `install_mod.py` stops and the old variant is gone | the installer removes all `bosota_*` folders first, then checks `dist/<id>/` and the audio, then copies (known behaviour, not changed) | produce the audio with the variant's `audio_recipe`, run again; the removed variant is not restored automatically |
| `install_mod.py`: "FEHLER: X4 läuft" ("X4 is running") | guard against swapping under a running game | close X4; `--force` skips the check (the check only runs for the default game folder anyway), but swapping under a running game can leave Boso silent |
| Access denied when deleting a mod folder | read-only folder attribute from OneDrive copies | the installer retries the deletion up to five times, clearing the attribute; if it still fails, delete the folder by hand |
| `process_audio.py`: every file fails | ffmpeg build without Rubberband (the pitch and time-stretch library), or ffmpeg not found | install the full build (`winget install Gyan.FFmpeg`) or pass `--ffmpeg <path to ffmpeg.exe>` |
| `voice_convert_elevenlabs.py tts-batch`: HTTP 402 | ElevenLabs answers `paid_plan_required`: library voices (professional voice clones) are blocked on the free plan (`docs/dev-team/LESSONS.md:31`) | use a premade voice or a paid plan |
| `voice_convert_elevenlabs.py quota`: HTTP 401 | the API key lacks the user-read permission needed for the subscription endpoint (`docs/dev-team/LESSONS.md:31`) | create a new key with default permissions in the ElevenLabs account settings |
| `tts-batch` ends with a traceback although all lines were generated | a network error in one worker thread is raised again only when the results are collected at the end; the remaining queued lines still run and are billed | rerun the same command; finished WAVs are skipped |
| `tts-batch`: many lines fail at once | any other 4xx answer except 429 (for example an invalid key or exhausted credits; the tool prints the status code) fails each line without retry | fix the key or top up the credits, rerun |
| `install_mod.py` raises `FileExistsError` | the target `extensions/ws_<number>` already exists (a rerun into a staging folder, or a subscribed item in the game folder); the copy does not overwrite and only `bosota_*` is cleaned | delete that `ws_<number>` folder first, then run again |
| `check_coverage.py` prints "game: 0 lines" and passes | wrong `--game-dir`/`X4_GAME_DIR` | read the line count; fix the path |
| `validate_mod.py` traceback `FileNotFoundError` | a `dist/<id>` folder without `content.xml` or diff, often a stale folder of a removed variant | delete the stale folder |
| `build_mod.py --only` builds nothing, exit 0 | typo in the variant key | check the key |
| `x4cat_extract.py` extracts 0 files | wrong catalog: on 9.00 the lines are in `03.cat`, not `01.cat` | find the catalog with `Select-String -Path "<game>\0*.cat" -Pattern "^voice-l049/10201/normal/" -List` ([ch. 3](03-game-archives-and-extraction.md)) |
| `WorkshopTool.exe publishx4`: Steam error 16 | creating an item together with a large payload (56 MB of audio) timed out | create the item with the XML files only, then upload the audio with `update` ([ch. 8](08-installing-and-releasing.md)) |
| `WorkshopTool.exe update`: Steam error 9 | `-preview` passed on the first update of a new item | update without `-preview` |
| Control characters in `config/variants.json` (invisible characters inside paths such as `build\venv`) | a Python script fed through a shell heredoc wrote Windows paths in normal string literals, so Python read `\v` as a vertical tab and `\1…` as an octal code | edit such files in an editor, or use raw strings (`r"…"`) |
| `python` "Permission denied" (seen in Git Bash) | broken Windows Store alias (the `python` stub in `WindowsApps`) | call the real `python.exe` by its full path, or disable the Python entries under "App execution aliases" in the Windows settings |

## Edge cases in the data

- **Alternate takes** (`30201430fp`): a second recording of the same line, marked by a letter suffix. It has no text of its own; the TTS and coverage tools fall back to the text of `30201430` (`tools/voice_convert_elevenlabs.py:137`).
- **Five textless ids**: `10417`, `10603`, `30226001`–`30226003` have no text entry, so the Will variants (the German text-to-speech builds `will` and `alien_ws`) keep processed original audio for them (step 3 of their `audio_recipe`).
- **German-only ids**: on 9.00, 574 ids exist only in the German track: pilot and crew phrases that were never recorded in English for this set (`docs/phase0-findings.md:23`). The English variant has none of them and the English game never requests them; no action needed.
- **`10201_comm_signalleak`** already has `noocclusion="true"` in the base game; an `add` would fail, so it is left out of the `noocclusion` item in each variant's `sound_attr_ops` ([ch. 4](04-variants-configuration.md)).
